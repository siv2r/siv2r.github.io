The sitting in one line For a continuous random variable, probability lives on small segments, never on points. The density is the CDF's slope, f=F′f = F'f=F′, every probability is an area under fff, and any single point carries exactly zero.

From staircase to ramp

In the discrete world (probability-distributions-and-random-variables) the CDF is a staircase and the PMF lives in the jumps: P(X=x)=F(x)−F(x−)P(X = x) = F(x) - F(x^-)P(X=x)=F(x)−F(x−), the jump height at xxx. A continuous CDF is a smooth ramp with no jumps at all. Apply the same jump formula and it forces P(X=x)=0P(X = x) = 0P(X=x)=0 for every single xxx. Nothing is left over for any individual point.

The interesting part is what falls out on the way. Writing the small difference at xxx gives F′(x) dxF'(x)\,dxF′(x)dx, and as dx→0  ⟹  P(X=x)=F′(x).dx→0dx \rightarrow 0 \implies P(X = x) = F'(x).dx \rightarrow 0dx→0⟹P(X=x)=F′(x).dx→0. It is the chapter's central object: f(x)=F′(x)f(x) = F'(x)f(x)=F′(x), the probability density function.

One cheap consequence worth pocketing: since endpoints carry zero, P(a<X<b)=P(a≤X≤b)P(a < X < b) = P(a \le X \le b)P(a<X<b)=P(a≤X≤b), and every half-open version in between. No more <<< vs ≤\le≤ anxiety.

Probability lives on segments (the dx view)

f(x)f(x)f(x) is not a probability. f(x) dxf(x)\,dxf(x)dx is: the probability that XXX lands in a tiny window of width dxdxdx around xxx. Density is probability per unit length, which means it carries units. My waiting-time example: XXX uniform on half an hour has density height 2 measured in hours and height 1/30 measured in minutes. Same random variable, same probabilities, different heights. Only height times width is real.

That also settles why a density can exceed 1. The only validity conditions are f≥0f \ge 0f≥0 everywhere and total area 1. Height 2 (or 3, or 100) is fine as long as the support is narrow enough. Unif(0,1/3)\text{Unif}(0, 1/3)Unif(0,1/3) sits at height 3 everywhere and is a perfectly legal distribution. The mantra: height is probability per unit length, only area is probability.

The same view is the right way to think about transformations. To understand Y=g(X)Y = g(X)Y=g(X), don't ask where a point goes, ask what happens to a small segment. The map ggg sends [x,x+dx][x, x + dx][x,x+dx] to a segment around g(x)g(x)g(x), and the probability mass f(x) dxf(x)\,dxf(x)dx riding on it is conserved. If the segment gets stretched, that mass spreads over more length, so the density drops. Compressed, the density rises.

The Uniform

Same support is not same distribution: the U² trap

A friend argues: U2U^2U2 still lands in (0,1)(0,1)(0,1), so it is still completely random there. The test comes from the Uniform section: completely random means flat PDF, which means linear CDF. Compute it: P(U2≤x)=P(U≤x)=xP(U^2 \le x) = P(U \le \sqrt{x}) = \sqrt{x}P(U2≤x)=P(U≤x​)=x​. Not linear. Same support, different distribution.

The segment view says where the mass went. Squaring pulls every value in (0,1)(0,1)(0,1) downward, compressing segments near 0, so the density piles up there. About 70% of draws land below 1/2, since 1/2≈0.707\sqrt{1/2} \approx 0.7071/2​≈0.707.

This is exactly the classic nonce-bias bug in ECDSA and Schnorr. Reduce a uniform 256-bit number mod the group order nnn and every residue is still possible, but residues below 2256 mod n2^{256} \bmod n2256modn get hit slightly more often. The support looks fine, the distribution is not uniform, and with enough signatures lattice attacks turn that tiny skew into the secret key. The flat-PDF test is the formal version of the check that catches it.
